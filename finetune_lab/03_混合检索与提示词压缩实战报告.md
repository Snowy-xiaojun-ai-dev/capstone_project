#  RAG 降本增效 (Hybrid Search + LLMLingua)

为了突破单纯向量检索（Dense）对专有名词（如型号、代码）不敏感的瓶颈，以及解决长文本导致大模型 Token 费用高昂的问题，本项目引入了混合检索与提示词压缩技术。

## 1. 核心技术实现
*   **双路混合检索 (Hybrid Search)**：同时初始化 `VectorIndexRetriever`（基于语义）与 `BM25Retriever`（基于关键词精确匹配），专治各种特定字母/数字组合。
*   **RRF 融合排序**：利用 `QueryFusionRetriever`，采用倒数排名融合（RRF）算法将双路召回的结果进行重排，确保最相关的信息排在前面。
*   **LLMLingua 提示词压缩**：在检索后、生成前引入 `PromptCompressor`，大幅剔除上下文中的冗余废话，直击“降本增效”痛点。

## 2. 实际运行效果与复盘

*![终端测试截图](./screenshot_terminal.png)

通过真实测试“型号 XR-2000 是什么”，我们验证了架构的有效性，同时也暴露了小模型的局限性：

### ✅ 成功点一：混合检索精准召回
*   **现象**：原始检索结果（558字符）成功将含有特定型号 `XR-2000` 的产品说明与薛之谦个人档案一并召回。
*   **结论**：BM25 结合向量检索，完美解决了纯语义模型对专有名词“泛化过度”导致的漏搜问题。

### ✅ 成功点二：LLMLingua 极致压缩
*   **现象**：LLMLingua 将 558 字符的原始文本，精准压缩到了 211 字符。
*   **结论**：压缩后仅保留了核心实体（薛之谦、XR-2000、荧光棒、控变色等），剔除了所有废话，极大降低了后续大模型 API 的 Token 成本。

### ⚠️ 踩坑反思：0.5B 模型在“关键词堆砌”下的幻觉
*   **现象**：在接收到 LLMLingua 压缩后的“关键词序列”时，0.5B 本地模型（qwen-medical）无法正确还原其语义逻辑，产生了严重的幻觉（将 XR-2000 误认为 2000 年发行的专辑衍生节目）。
*   **工程反思**：LLMLingua 的极高压缩率是以**牺牲语法结构**为代价的。对于具备 7B 以上参数量的大模型，它可以自动脑补语法；但对于 0.5B 小模型，长上下文连贯性是它理解问题的前提。在企业级落地中，若使用小参数模型作为生成端，应适当调大 LLMLingua 的 `target_token`（如 500），或者在压缩后使用正则进行强行格式兜底。
