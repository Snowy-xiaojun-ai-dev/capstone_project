# 《大模型 LoRA 微调与私有化部署实战报告》

## 一、 项目背景与目标
本项目旨在掌握大模型私有化落地的核心链路。通过 LLaMA-Factory 对 Qwen2-0.5B 进行 LoRA 微调，将模型量化为 GGUF 格式，最终通过 Ollama 进行本地托管，并完成 API 接口的代码级调用。

## 二、 核心流程与数据对比
*   **模型微调**：利用 LLaMA-Factory (WebUI) 基于自定义的“薛之谦”数据集进行 LoRA 微调，并成功导出评估结果。
*   **模型合并与量化**：
    *   **FP16 合并模型**：约 988 MB。
    *   **4bit (Q4_K_M) 量化 GGUF**：约 373.7 MB。
    *   **结论**：量化后体积缩减约 62%，极大降低了本地部署门槛。
*   **Ollama 托管**：编写 `Modelfile`（设定 Temperature=0.7，配置 System Prompt），通过 `ollama create` 成功将模型注册为本地服务。

## 三、 接口调用验证 (Python)
*   通过 OpenAI SDK 成功直连本地 Ollama 的 `11434` 端口，实现了流式输出。

## 四、 深度踩坑记录（企业级工程排雷）
在尝试将模型接入 RAGFlow 知识库构建 WebUI文件 时，遭遇了严重的容器化环境冲突：
1.  **SSRF 安全防护拦截**：RAGFlow 强制拦截对本地局域网 IP 的请求，导致模型无法连接。
2.  **Kvrocks 依赖缺失**：Go 架构强制依赖 Kvrocks，但 macOS 配置文件未包含该服务，导致容器无限重启。
3.  **版本错配灾难**：镜像、源码、配置文件三者版本不一致，引发 `mysql_migration.py` 找不到等一连串问题。
*   **最终方案**：彻底放弃图形界面，清理 30GB 容器垃圾，转向纯代码控制的 LangChain 架构。

## 五、 经验总结
1.  **容器网络隔离**：宿主机与 Docker 容器通信，必须处理 `host.docker.internal` 及安全策略。
2.  **版本对齐铁律**：开源框架降级时，镜像、配置文件必须完全匹配，否则会引发雪崩式报错。
