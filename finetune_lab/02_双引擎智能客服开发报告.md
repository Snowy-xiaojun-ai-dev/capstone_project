# Hybrid RAG + LoRA 微调智能客服系统

## 1. 系统架构
本项目摒弃了单一的 RAG 或纯微调方案，采用混合双引擎架构：
[PDF 文档] ➡️ [PyPDFLoader 解析] ➡️ [Recursive 切分] ➡️ [BGE Embedding] ➡️ [Chroma DB] ⬇️
                                                                       [bge-reranker 重排序] ⬇️
[用户输入] ➡️ [FastAPI 接口] ➡️ [LangChain 组装 Prompt] ➡️ [Ollama 托管微调模型 (cs-assistant-v1)] ➡️ [流式输出]

## 2. 核心突破
*   **混合增强**：底层用 RAG 提供外部事实记忆（查得准），上层用 LoRA 微调约束大模型角色设定与固定话术（说得好）。
*   **检索优化**：在 LangChain 中手写检索逻辑，并引入 `bge-reranker-base` 模型进行 Rerank 重排序，从海量文档中精准提取 Top-K 相关段落，有效提升了召回精度。
*   **工程封装**：通过 FastAPI 将整套链路封装为标准 RESTful API，支持 SSE (Server-Sent Events) 流式打字机输出，符合大厂高并发服务规范。

## 4. 工程优化避坑（面试必杀技）

*   **Chunking 策略选择**：经过测试，`chunk_size=500` 搭配适当的 `overlap` 最适合中文产品手册，能有效避免长段落被截断导致语义丢失。
*   **API 输出截断与幻觉控制**：初期因 `num_predict=200` 限制，导致长文本回答被强行掐断。后续将参数放宽至 `512`，并在 LangChain 的 Prompt 模板中注入了 **Few-shot（少样本示例）** 强提示，强迫模型遵守格式。
*   **小模型指令遵循崩塌反思（核心痛点）**：在测试 C 中发现，0.5B 模型在同时处理“长上下文（RAG 注入）”和“强格式约束（Prompt 注入）”时，注意力机制容易失效，导致丢失开场白。
    *   *工程兜底方案*：若算力受限无法升级至 1.5B/7B 以上模型，则需在 FastAPI 代码层加入正则表达式或字符串拼接，进行“格式后处理兜底”。
*   **环境兼容性排雷**：在 macOS 下，成功配置 `HuggingFaceEmbeddings` 的本地加载，避开了网络下载痛点；同时利用 `uvicorn --reload` 实现了代码热更新，提升了联调效率。
